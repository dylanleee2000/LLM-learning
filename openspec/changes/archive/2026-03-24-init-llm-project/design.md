## Context

当前是一个空的 LLM 学习目录，需要建立一个结构化的 Python 项目来组织日常学习脚本。项目目标是支持多种 LLM 技术实验：基础调用、RAG、Agent 等。

## Goals / Non-Goals

**Goals:**
- 建立清晰的项目目录结构
- 创建可复用的核心模块（LLM 初始化、配置、Prompt 模板）
- 实现 RAG 基础组件（分块、向量存储、检索）
- 搭建 LangGraph Agent 框架
- 提供示例脚本展示各种 LLM 用法

**Non-Goals:**
- 完整的生产级应用
- 复杂的部署流程
- 多用户支持
- 持久化数据库（使用本地文件/向量库即可）

## Decisions

### 1. 使用 python-dotenv 管理环境变量
- **选择**: 使用 `.env` 文件 + `python-dotenv` 加载
- **理由**: 简单直观，不暴露密钥到代码中，支持多种 API Key

### 2. 多模型支持设计
- **选择**: core/llm_init.py 提供统一接口，支持 OpenAI、通义千问、Ollama
- **理由**: 学习过程中可能需要对比不同模型效果，统一接口便于切换

### 3. 向量存储选择
- **选择**: 使用 ChromaDB 作为默认向量库
- **理由**: 轻量级、本地运行、无需额外服务，适合学习场景

### 4. Agent 框架
- **选择**: 使用 LangGraph 构建 Agent
- **理由**: 官方推荐，支持复杂工作流，可视化调试

### 5. 依赖管理
- **选择**: 使用 requirements.txt 统一管理
- **理由**: 简单通用，便于分享和复现环境

## Risks / Trade-offs

- **风险**: 依赖包版本冲突 → **缓解**: 使用虚拟环境，requirements.txt 锁定版本
- **风险**: API Key 泄露 → **缓解**: .gitignore 忽略 .env，README 中明确提醒
- **风险**: 目录结构后期需要调整 → **缓解**: 保持模块化，便于重构
